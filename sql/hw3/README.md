# Склад — домашнее задание 3

## Запуск

Требуются Python 3.10+, uv и работающий PostgreSQL. Для сборки psycopg2 могут
понадобиться установленные PostgreSQL/libpq и компилятор.

```sh
uv sync
uv run python main.py
```

Перед запуском укажите подключение в `hw3/config.yaml` либо через переменные
`PGDATABASE`, `PGUSER`, `PGPASSWORD`, `PGHOST`, `PGPORT`. Пароль можно хранить
в стандартном файле PostgreSQL `~/.pgpass`; пароль в репозитории не хранится.
Для другого файла YAML задайте `WAREHOUSE_CONFIG`.
База данных должна существовать, пользователь должен иметь право создавать
схему и таблицы в ней. Базу приложение не создаёт.

Пример для локальной установки PostgreSQL:

```sh
export PGDATABASE=postgres
export PGUSER=postgres
export PGHOST=localhost
export PGPORT=5432
uv run python main.py
```

В главном меню:

1. Выберите **2**, чтобы создать схему и таблицы. Повторный вызов сохраняет данные.
2. При желании выберите **3**: в пустую базу загрузятся пять помещений и пять
   стеллажей из hw2. Повторная загрузка в непустую базу запрещена.
3. Выберите **1** для работы с помещениями.

Также поддерживаются `uv run python -m hw3.main` и `uv run python hw3/main.py`.
Путь к настройкам не зависит от текущего рабочего каталога.

## Возможности интерфейса

- Помещения: список, добавление, изменение, удаление, переход к стеллажам.
- Стеллажи выбранного помещения: список, добавление, изменение, удаление.
- Оба списка разбиты на страницы по пять записей: `n` — вперёд, `p` — назад,
  `r` — обновить. После удаления страница автоматически ограничивается доступным диапазоном.
- Запись выбирается по **номеру строки текущей страницы**, от 1 до 5.
  Внутренние ключи не выводятся и не запрашиваются. Номер стеллажа — предметный
  номер на складе, не технический идентификатор.
- `/отмена` отменяет форму; при выборе строки `0` отменяет выбор.
  При редактировании Enter оставляет текущее значение. Удаление подтверждается словом `да`.
- Пустое помещение можно удалить. Помещение со стеллажами удалить нельзя:
  сначала нужно удалить стеллажи. Это соответствует `ON DELETE RESTRICT` из hw1.
  Изменение названия или характеристик помещения сохраняет связь со стеллажами.
- Одинаковые названия помещений допустимы, как в hw1; выбор по строке однозначен.
  Номер стеллажа уникален внутри помещения, в разных помещениях может повторяться.

## Проверки и обработка ошибок

До обращения к базе проверяются непустое название, управляющие символы,
положительные целые числа до 2147483647, точность и диапазон NUMERIC,
положительность размеров, объёма и нагрузки, температура от −273,15 °C,
влажность 0–100% и порядок границ диапазонов. Десятичный разделитель — точка
или запятая; лишние дробные знаки отклоняются без скрытого округления.
NaN, Infinity и экспоненциальная запись не допускаются.

Ограничения PostgreSQL дополнительно защищают данные при конкурентных действиях.
Все пользовательские значения передаются параметрами; идентификаторы SQL
формируются через `psycopg2.sql.Identifier`. SQL из пользовательского ввода не исполняется.
Изменение и удаление сверяют показанную версию записи, чтобы не затереть чужие изменения.

Каждое действие выполняется в транзакции. При ошибке происходит откат,
выводится понятное сообщение без SQL и технических ключей. Соединение
восстанавливается при следующем действии. Ожидания соединения, запросов и
блокировок ограничены. При потере связи во время сохранения пользователь
получает предупреждение о неизвестном результате и необходимости обновить список.
EOF и Ctrl+C завершают работу без traceback.

## Проверка

```sh
uv run python -m unittest discover -s tests -v
```

Без специальной настройки запускаются проверки ввода и выбора строк,
а интеграционные тесты пропускаются. Для всех тестов укажите **отдельную тестовую
базу** переменными PostgreSQL и включите `WAREHOUSE_TEST_DB=1`:

```sh
PGDATABASE=warehouse_test WAREHOUSE_TEST_DB=1 uv run python -m unittest discover -s tests -v
```

**Интеграционные тесты очищают rooms и racks в схеме warehouse_hw3 указанной базы.**
Проверяются CRUD, ограничения связей, повторяющиеся номера, восстановление
после ошибки, SQL-инъекции, конфликт изменений, страницы, изоляция стеллажей
разных помещений, демонстрационные данные и навигация интерфейса.

- `hw3/schema.sql` — схема помещений и стеллажей из hw1.
- `hw3/demo.sql` — соответствующие примеры из hw2.
- `hw3/main.py` — консольный интерфейс.
- `hw3/validation.py` — проверка типов и диапазонов.
- `hw3/dbconnection.py` — транзакции и обработка ошибок PostgreSQL.
- `hw3/dbtable.py`, `hw3/tables/` — параметризованные операции над таблицами.
- `tests/test_project.py` — автоматические проверки.
