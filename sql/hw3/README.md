## Запуск

1. Установить PostgreSQL и Python 3.10+.
2. Создать **пустую** БД `warehouse`, например `createdb -U postgres warehouse`, или выбрать уже существующую базу, где расположены `rooms` и `racks` из ДЗ.
3. Установить зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

4. Настроить `config.yaml`: `dbname`, `user`, `host`, `port`, `dbtableprefix`. Пароль можно указать в `config.yaml` или передать через `PGPASSWORD` (предпочтительно); также поддерживаются `PGDATABASE`, `PGUSER`, `PGHOST`, `PGPORT`.
5. Запускать из любой рабочей папки:

   ```bash
   python main.py
   ```

Программа сама выполнит `CREATE TABLE IF NOT EXISTS` для `rooms` и `racks` (без удаления имеющихся записей). При желании можно заранее выполнить `schema.sql`, но это **не обязательно**. Если в БД уже есть таблицы с такими именами, они должны соответствовать схеме из ДЗ; `IF NOT EXISTS` не заменяет/не исправляет чужие таблицы.

## Функциональность

- Просмотр помещений, добавление, редактирование, удаление.
- Просмотр стеллажей выбранного помещения, добавление, изменение, удаление.
- Пагинация по 5 строк на страницу. `n/p` — перемещение между страницами.
- Для редактирования/удаления выбирается **порядковый номер из списка текущей страницы**. `room_id`, `rack_id` и иные технические ключи **не показываются и не вводятся**.
- В режиме редактирования пустой ввод оставляет поле прежним. Символ `!` отменяет любую операцию ввода.
- При удалении подтверждение `да` обязательно. Помещение, содержащее стеллажи, удалить нельзя (правило `ON DELETE RESTRICT` из ДЗ): сначала удалить его стеллажи.
- Номера стеллажей уникальны внутри каждого помещения, но могут повторяться в разных помещениях.
- Проверки реализованы на уровне Python и БД. Ввод с запятой вместо точки в числах допустим; избыточные знаки дробной части, `NaN`, отрицательные размеры, значения за пределами `NUMERIC` и `INTEGER` отклоняются до SQL.
- Все значения передаются в SQL через параметры `%s`; идентификаторы схемы и таблиц — через `psycopg2.sql.Identifier`. Запросы не собираются конкатенацией пользовательского ввода.
- Каждая операция записи выполняется в транзакции с откатом при исключении. Ошибки целостности и уникальности переводятся в понятные сообщения.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Модульные тесты проверяют типы и границы входных значений. **Интеграционная проверка PostgreSQL требует работающего сервера** и корректно заполненного `config.yaml`.
